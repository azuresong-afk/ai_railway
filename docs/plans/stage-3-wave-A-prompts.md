# Этап 3, волна A: промпты

Составлены 22.10.2026 (поток H9) по `docs/plans/stage-3.md`. Запускать после того, как владелец подтвердит план этапа 3 и решения Р1, Р2 (статус плана в `stage-3.md` — «подтверждён»), и после слияния этапа 2 в `main`.

Общие правила для всех потоков:
- Интеграционная ветка `claude/stage-3-integration` от `main` после слияния этапа 2 (создаёт первый запущенный поток: `git push origin origin/main:refs/heads/claude/stage-3-integration`, если её ещё нет). Push в неё — только через merge: без rebase, amend и force-push. PR не открывать.
- Go 1.27.3 (иначе `GOTOOLCHAIN=go1.27.3`). Команды — простые одиночные в формах из `permissions.allow` в `.claude/settings.json` (без `export`, пайпов, `&&`, `;`, heredoc), файлы — Edit/Write. `golangci-lint`, `govulncheck`, `sbom-utility` в облаке не скачиваются — это не провал задачи, проверяются в CI. Перед `make check` или `make sast` удалить `web/node_modules`. PostgreSQL для тестов: `pg_ctlcluster 16 main start`, `AISEC_TEST_DATABASE_URL`.
- Номера: ADR закреплены (A1 — 0018, A2 — 0019, A3 — 0020); миграции — со следующего свободного номера (0027) у влившегося первым, перед коммитом сверить с интеграционной веткой.
- RBAC: `x-permission` у каждой новой операции в `api/openapi.yaml`, право в `internal/auth/permissions.go`, `make rbac-matrix`; у каждого эндпоинта — тест на отказ; у каждого действия администратора — код аудита в `internal/audit/catalog.go`.
- Тесты с БД и e2e — без ID строки матрицы в имени. Нестабильные под `-race`: `TestRegexLinearTime`, `TestDM11_IncrementalLongListWithCode`, `TestServerSinkSplitsLargeBatch`.
- После каждого шага: строка в журнале `stage-3.md`, статус задачи, коммит, `git fetch`, merge интеграционной ветки, push в рабочую ветку и в интеграционную.
- Отчёт после каждой задачи — до 8 строк: что сделано, коммит, документы, что проверить руками, вопросы. Решения, не противоречащие ТЗ и плану, поток принимает сам по общепринятой практике и записывает рядом с задачей; спрашивает, только если решение противоречит ТЗ или меняет объём этапа.

## A1. Задачи 3.1–3.3 — ротация ключей
**Модель:** Opus 5.5, effort high. Зависит от этапа 2 (закрыт).

```
Поток A1 этапа 3: задачи 3.1, 3.2, 3.3 из docs/plans/stage-3.md (ротация ключей, решение Р1, H-Р12 этапа 2; Н27). Отвечай на русском.
1. Ветки. git fetch origin. В свою рабочую ветку: git merge --ff-only origin/claude/stage-3-integration. Push в claude/stage-3-integration разрешаю; история только через merge.
2. Защита от повтора (docs/plans/roadmap.md): статус плана этапа 3 — «подтверждён», иначе остановись и сообщи. Статусы 3.1–3.3, журнал и метки «задача 3.N этапа 3» в git log: готова или в работе — пропусти её и сообщи.
3. Захват: статус «в работе (дата, поток A1)», коммит docs, push в интеграционную ветку. Отклонён — fetch, merge, проверь снова.
4. 3.1: ADR-0018 «Ротация ключей» — ключ подписи пакетов, ключ аудита, корень внутреннего УЦ, мастер-ключ, ключ данных; версии ключей, период перекрытия (по умолчанию 30 суток), что делает сервер и шлюз на каждом шаге, откат, аудит, альтернативы. Закрепление ключа получателя HPKE за шлюзом при регистрации и его смена только перерегистрацией (Н27, ADR-0009 п. 3). Перед кодом пришли короткий план; работу начинай сразу.
5. 3.2: aisec-cli keys rotate-master и keys rotate-data. Новый ключ данных — новая версия для новых шифрований; фоновое перешифрование секретов провайдеров, TOTP, ключа HMAC псевдонимов пачками с возобновлением после сбоя; старая версия выводится только после перешифрования всех строк; счётчик sealed и AAD — по ADR-0007. Мастер-ключ — перешифрование ключа данных, файл через os.Root, права 0400, старый файл не удаляется автоматически. Тесты: прерывание на середине, повторный запуск, расшифровка после ротации, отказ при чужом мастер-ключе.
6. 3.3: ротация ключа подписи пакетов и ключа аудита с перекрытием (шлюз принимает оба ключа до конца перекрытия; ключ аудита — новая контрольная точка); новый корень УЦ с перекрытием и перевыпуском сертификатов шлюзов при heartbeat; доставка нового ключа подписи и корня шлюзам в пакете конфигурации (остаток 2.13). Тесты на каждый отказ: пакет старым ключом после перекрытия, сертификат старого корня после перекрытия, подмена ключа в пакете.
7. Трогай только: internal/keyring/, internal/crypto/ (ключи, без своих алгоритмов), cmd/aisec-cli (keys), internal/policy/bundle*, internal/gateway/ (загрузка пакета и доверие), internal/gwregistry/ (ключ HPKE, перевыпуск), свои миграции, docs/adr/0018-*.
8. Документы: docs/cert/security-functions.md (ЗИ.1, ИАФ.10, ОЦЛ.3), docs/cert/attack-surface.md (команды, поля пакета), docs/cert/threat-model.md (компрометация ключа), руководство администратора, раздел 14 (ротация), stage-3.md (журнал, статусы).
9. make check один раз перед коммитами кода; итог — в отчёт. Отчёт до 8 строк после каждой задачи.
```

## A2. Задачи 3.4–3.5 — поставка пилота в docker compose

```
Поток A2 этапа 3: задачи 3.4 и 3.5 из docs/plans/stage-3.md (поставка пилота в docker compose, решение Р2; Н34, Н35, ЗИ.5, ОБН.1). Отвечай на русском.
1. Ветки — как у A1 (merge --ff-only из claude/stage-3-integration, push только через merge).
2. Защита от повтора: план этапа 3 «подтверждён», иначе остановись. Статусы 3.4, 3.5, журнал, git log — готова или в работе: пропусти и сообщи.
3. Захват: статус «в работе (дата, поток A2)», коммит docs, push.
4. 3.4: ADR-0019 «Поставка пилота»: образы aisec-server, aisec-gateway, aisec-cli на scratch со статическими бинарниками, USER 65534, read_only, cap_drop ALL, no-new-privileges, секреты и ключи — файлы через secrets compose, тома для состояния шлюза и резервных копий; PostgreSQL — официальный образ из реестра заказчика (продукт его не распространяет); порты по attack-surface.md; процедура обновления docker compose pull/up с проверкой подписи манифеста (ОБН.1 в части MVP); альтернативы (distroless, свой образ PostgreSQL). 7. Сеть: в образах и compose — никаких внешних адресов, CDN, телеметрии; healthcheck — локальный.
8. Документы: docs/cert/security-functions.md (ЗИ.5, ОБН.1), docs/cert/attack-surface.md (порты, тома, переменные окружения compose), docs/cert/components.yaml (образ PostgreSQL как внешний компонент — только после согласия владельца, иначе пометка в отчёте), черновик руководства установки (docs/user/install-pilot.md — полный текст в 3.31), stage-3.md.
9. make check один раз перед коммитами кода; итог — в отчёт. Отчёт до 8 строк. Ключа производителя для манифеста нет — собирай с тестовым ключом и явно пиши в отчёте, что образ не для передачи заказчику.
```
