## 0.5 SAST: SARIF и сверка разметки — 0,5 дня
**Результат.** `make sast` формирует `build/sast/gosec.sarif` (через golangci-lint или gosec) и сверяет его с разметкой в `docs/cert/sast-triage/triage.yaml`: каждое срабатывание должно быть размечено (`true_positive` / `false_positive` с обоснованием), иначе сборка падает. Утилита `tools/sast-triage` — разбор SARIF и файла разметки, отпечаток срабатывания не зависит от номера строки: это нормализованная строка из правила, файла и фрагмента кода, без хеширования (Р9).
**Файлы.** `tools/sast-triage/`, `docs/cert/sast-triage/README.md`, `docs/cert/sast-triage/triage.yaml`.
**Проверки.** Модульные тесты: новое срабатывание → ошибка, размеченное → проходит, разметка без срабатывания → предупреждение. Fuzz-тест разборщика SARIF (`FuzzParseSARIF`) и файла разметки.
**Документы (раздел 9).** `sast-triage/` (формат разметки), `fuzzing.md` (новые цели).
**Статус.** готова. `make sast`: gosec → `build/sast/gosec.sarif`, `tools/sast-triage` сверяет с `docs/cert/sast-triage/triage.yaml` (неразмеченное или истинное — ошибка, устаревшая разметка — предупреждение) и выписывает подавления `//nolint:gosec` в `build/sast/suppressed.md`. Отрицательный сценарий проверен вручную. Входит в `make check`.

Затрагивает `internal/crypto` — этот план и есть требуемое `CLAUDE.md` согласование.
**Результат.**

## 0.13 Шлюз: прозрачный прокси `/v1/chat/completions` с SSE — 1 день
**Результат.** `httputil.ReverseProxy` (через `Rewrite`) на один upstream. Только `POST /v1/chat/completions`, остальное — 404 или 405. **Проверки.** Модульные тесты с `httptest`: обычный ответ; SSE приходит по частям, а не одним куском; 413 на большое тело; 405 и 404; upstream недоступен → 502; upstream завис → таймаут; клиентский `Authorization` не доходит до upstream; разрыв клиентом отменяет upstream-запрос. Fuzz-тест обработчика `FuzzProxyHandler` (ТЗ 8.5 — обработчики входящих HTTP-запросов).
**Документы (раздел 9).** `attack-surface.md`, `threat-model.md` (STRIDE для шлюза — первые угрозы), `fuzzing.md`.
