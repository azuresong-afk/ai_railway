# Дорожная карта: что сделано, что дальше и зачем

Состояние на 20.10.2026. Источники: `roadmap.md`, `stage-1.md`, `stage-2.md`. Этот файл — обзор для человека, источник истины по статусам остаётся в планах этапов.

## Общая картина
Продукт — шлюз-посредник между приложениями и языковыми моделями плюс веб-консоль. Шлюз проверяет запросы и ответы, прячет персональные данные, ловит промпт-инъекции и утечки. Работа идёт по шести этапам по ТЗ (раздел 14). Этап 1 закрыт, план этапа 2 ждёт подтверждения.

## Этап 0 — основа. Готов
Каркас репозитория, сборка и `make check`, линтеры и проверки безопасности, документы для сертификации, mock-провайдер. **Зачем:** требования безопасной разработки (ФСТЭК) действуют с первого коммита, поэтому проверки и документы нужны до появления функций.

## Этап 1 — ядро шлюза. Закрыт 20.10.2026
**Цель:** шлюз, который принимает запрос в формате OpenAI, проверяет его, скрывает ПДн, блокирует инъекции, пересылает модели и проверяет ответ. Без интерфейса и сервера управления: настройки берутся из локального файла.

| Что | Зачем |
|---|---|
| События, конфигурация, ключи приложений, аутентификация (1.1–1.4) | Только свои приложения ходят в шлюз; каждое срабатывание записывается |
| Разбор запросов и потоков, провайдеры OpenAI-совместимые, GigaChat, YandexGPT (1.5–1.9) | Любой вход ограничен и проверен; шлюз работает с моделями, которые используют в России |
| Восемь детекторов с корпусами и стендом качества (1.10–1.18) | ПДн, секреты, скрытые символы, инъекции RU/EN, канарейка, вынос данных через ссылки, списки заказчика, квоты |
| Политики, псевдонимизация, конвейер, проверка ответа и `tool_calls` (1.19–1.23) | `monitor` и `enforce`, модель не видит ПДн, а пользователь получает ответ с настоящими данными |
| Check API, эмбеддинги, mock-llm, e2e по критериям приёмки (1.24–1.26) | Доказательство, что этап выполнен |
| Метрики, бенчмарки, документы для сертификации, проверка `vendor/` (1.27–1.28) | p95 задержки детекторов 3,8 мс при цели 30 мс; неизменность зависимостей |
| Итоговое ревью всего этапа | 1 критичное и 5 важных замечаний исправлены: обход склейкой частей сообщения, учёт токенов без `usage`, подмена модуля через `replace` и др. |

Осталось вне этапа: `make lint`, `sast`, `vuln`, `sbom` подтвердить в CI при слиянии в `main`; e2e эмбеддингов и Check API; нагрузка 500 RPS (запас 1,6× только на детекторах); длинные ответы в `incremental` в e2e.

## Этап 2 — сервер управления и функции безопасности. План ждёт подтверждения
29 задач (около 28 дней), волны A–G по три потока: хранилище и миграции, криптография (пароли, шифрование, подпись, TOTP), журнал аудита с цепочкой хешей, вход и роли, приложения и политики в сервере, подписанные пакеты для шлюзов, mTLS, приём событий, контроль целостности, резервная копия, веб-консоль при строгом CSP. **Зачем:** это функции безопасности, которые проверяет ФСТЭК; без них нет пилота с консолью. Подробно — `stage-2.md`.
