# Параллельная работа над этапом 1

Остаток этапа 1 (шаги 1.1–1.14 `roadmap.md`) разбит на волны. Потоки одной волны не зависят друг от друга и могут идти одновременно — каждый в отдельном потоке (Thread) проекта. Следующая волна начинается, когда готовы задачи, от которых она зависит. Правила `roadmap.md` (защита от повтора, документация, метки коммитов) действуют без изменений; здесь — только то, что добавляет параллельность.

Состояние на 20.10.2026: все волны A–E выполнены, этап 1 закрыт (`stage-1.md`). Параллельная работа над этапом 2 — `stage-2.md`, раздел «Параллельная работа».

## Протокол параллельного потока
1. **Интеграционная ветка** — `claude/project-thread-0ti8i0` (далее ИНТ): в ней всё, что сделано на этапе 1, включая этот файл. У каждого потока своя рабочая ветка; запуская промпт, владелец разрешает потоку push и в ИНТ.
2. **Старт.** `git fetch origin`, затем `git merge --ff-only origin/<ИНТ>` в рабочую ветку (ветка потока создаётся из `main`, где этой работы нет).
3. **Защита от повтора и захват** — по `roadmap.md`, но коммит «в работе» отправляется в ИНТ: `git push origin HEAD:<ИНТ>`. Push отклонён — `git fetch`, `git merge origin/<ИНТ>`, проверить статус снова. Так два потока не возьмут одну задачу.
4. **Работа** — в рабочей ветке; трогать только файлы из колонки «Файлы» своего потока. Нужен чужой файл — минимальная правка и строка в отчёте.
5. **Сдача.** `git fetch origin && git merge origin/<ИНТ>`, затем тесты затронутых пакетов и `make check` один раз, затем `git push origin HEAD` и `git push origin HEAD:<ИНТ>`. Push в ИНТ отклонён — повторить merge и push; `make check` повторять, только если merge изменил Go-код.
6. **Конфликты в общих документах** (`stage-1.md`, `docs/detectors.md`, `threat-model.md`, `builtin.go`, `Makefile`) — сохранить строки обеих сторон: в таблице задач — свою строку, в журнале — все строки по дате, в `builtin.All` — все детекторы. Конфликт в чужом коде — остановиться и спросить владельца.
7. **История ИНТ не переписывается**: без rebase, amend и force-push, только merge.
8. PR не создавать.

## Выбор модели (семейство Claude 5)
| Модель | Когда | Режим рассуждения |
|---|---|---|
| Opus 5.5 | строка Opus в `roadmap.md`: безопасность, детекторы и разборщики недоверенного ввода, политики, псевдонимизация, конвейер, ревью, закрытие этапа | high |
| Sonnet 5.5 | строка Sonnet: обычный код, mock-сервисы, e2e, метрики, документы | medium |
| Haiku 5.5 | только чтение: статус, проверка волны | low |

Экономия без потери качества: сложный код на Sonnet не переносится; вместо этого Sonnet получает задачи, где ошибка ловится тестами, а всё, что на Sonnet затронуло код из строки Opus, проходит ревью на Opus (шаги 1.6, 1.9, 1.13).
