```

1. Ветки — как в волне A: git fetch origin, git merge --ff-only origin/claude/stage-3-integration в свою ветку, push в claude/stage-3-integration только через merge. PR не создавать.

3. Захват: статус «в работе (дата, поток D1)», коммит docs, push.
4. Отметки в событии: «ложное срабатывание» и «подтверждено» (с комментарием до 1 000 символов), хранятся отдельно от события (событие неизменяемо), каждая — запись в аудит; отметка «ложное срабатывание» возвращает в ответе API черновик исключения по этому событию. Отметки видны в фильтрах событий. Содержимое запроса в отметку и черновик не копируется — только детектор, шаблон или хеш фрагмента.
5. Исключения — часть версии политики (новая версия, ADR-0016, неизменяемость старых): условие (детектор обязательно; плюс одно или несколько: шаблон или хеш фрагмента, приложение, пользователь), срок действия обязателен (по умолчанию 30 суток, не больше 365), автор и причина. Добавление исключения и продление — ослабление защиты: повторная проверка паролем или кодом TOTP и DM-40 через правила B2. Исключение не может отключить детектор целиком для всех приложений одним условием — такой ввод отклоняется. Истёкшие исключения шлюз не применяет без перевыпуска пакета (проверка срока на шлюзе по времени), сервер показывает их как истёкшие.
6. Пакет и шлюз: раздел исключений в пакете конфигурации (рядом с разделами A1 и B3, их не менять), шлюз применяет исключение после срабатывания детектора и до решения политики; событие получает признак «пропущено по исключению» с ID исключения (без содержимого). Счётчик ревизии конфигурации (3.34) увеличивается при изменении исключений.
7. API: отметки событий, список и создание исключений в версии политики, черновик из события — x-permission у каждой операции (новые права по правилу RBAC; создание исключения — policies.manage, только security_admin; отметка — оператор безопасности), тест на отказ для каждого эндпоинта, коды аудита в catalog.go. Входы — с лимитами и валидацией, fuzz на разбор условия исключения.
8. Тесты: модульные на применение исключения в шлюзе (совпадение, несовпадение, истёкшее, другое приложение) и на отклонение слишком широкого условия; e2e на живой PostgreSQL «ложное срабатывание → исключение → запрос больше не блокируется» (критерий приёмки этапа, имя без ID строки), и обратный — после истечения снова блокируется.
9. Трогай только: internal/policy/ (исключения, версии), internal/policy/bundle* (раздел исключений), internal/events/ (отметки, признак в событии), internal/gateway/ (применение), internal/api/ (свои эндпоинты), api/openapi.yaml (свои пути), internal/auth/permissions.go, internal/audit/catalog.go, test/e2e/ (свой тест), свои миграции. C1 параллельно правит internal/events (агрегаты) — перед каждым push fetch и merge.
10. Документы: ADR-0016 (раздел про исключения, не меняя принятых решений), docs/cert/security-functions.md, docs/cert/attack-surface.md (эндпоинты, поля пакета), docs/cert/threat-model.md (злоупотребление исключениями), матрица прав, stage-3.md. Затем cert-reviewer на дифф; важные замечания исправь до коммита.
11. make check один раз перед коммитом кода; итог — в отчёт. Отчёт до 8 строк.
```
