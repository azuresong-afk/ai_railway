Ключ хранится зашифрованным ключом данных с AAD места хранения (ADR-0007) и перешифровывается при rotate-data (как секреты провайдеров), в ответах API — только сведения о сертификате и признак «ключ задан». В шлюз — разделом пакета конфигурации, ключ — через HPKE для конкретного шлюза (как секреты провайдеров, 2.13); разделы A1, B3, D1 не трогать. Шлюз переключает TLS на адресе приложений без перезапуска; без сертификата заказчика — прежнее поведение. Оповещение за 30 и 7 суток до истечения — условием cert_expiry в internal/sysstatus и правилом DM-44 B2 (существующее, расширь на сертификат заказчика). API с x-permission (новое право по правилу RBAC, только system_admin или security_admin по матрице ТЗ 7), тест на отказ, аудит загрузки и замены. Fuzz на разбор загружаемого PEM.

Правила фронтенда из CLAUDE.md (без dangerouslySetInnerHTML, токены не в хранилище браузера, строгий CSP).
6. 3.28: ADR-0021 «Распределённые квоты при нескольких шлюзах»: выбор плана — счётчики на сервере с арендой лимита шлюзом (доля квоты на срок, возврат остатка, поведение при недоступности сервера — fail-open или fail-closed по fail_mode приложения), альтернативы (общий Redis — отклонено, ТЗ 4.2 без брокеров; равное деление; только локально), последствия для жёсткого бюджета B3. Реализация — этап 4, в ADR это прямо сказано.
7. Тесты: цепочка без корня, просроченный, чужое имя, ключ не от сертификата, слабый ключ, лишние блоки PEM; шлюз — переключение TLS и откат при неверном разделе пакета; PG-тест хранения без ID строки; отказ в доступе.
8. Трогай только: internal/apps/ (сертификат), internal/crypto/ (разбор и проверка цепочки, без своих алгоритмов), internal/policy/bundle* (раздел сертификата), internal/gateway/ (TLS по пакету), internal/sysstatus/ (cert_expiry), internal/alerting/ (только расширение DM-44), internal/keyring/ (перешифрование при ротации), internal/api/ (свои эндпоинты), api/openapi.yaml (свои пути), internal/auth/permissions.go, internal/audit/catalog.go, web/src/apps/ConnectWizard.tsx, свои миграции, docs/adr/0021-*.

Затем cert-reviewer на дифф; важные замечания исправь до коммита.
