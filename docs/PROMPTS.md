# Промпты для Claude Code

Промпты рассчитаны на ТЗ версии 0.5. Требования и правила живут в `CLAUDE.md` и `docs/SPEC.md`, поэтому промпты короткие: они запускают шаги работы, а не пересказывают ТЗ.

## Как пользоваться
1. Положите в корень пустого репозитория `CLAUDE.md`, папку `docs/` и скрытую папку `.claude/` (настройки и сабагент `cert-reviewer`). Сделайте первый коммит.
2. Запустите Claude Code в корне репозитория. Для промптов 0, 1 и 3 включите режим планирования (Shift+Tab): Claude покажет план и ничего не изменит.
3. План каждого этапа хранится в `docs/plans/stage-N.md` со статусами задач. Между задачами очищайте контекст командой `/clear`, а новую сессию начинайте с промпта «Продолжить работу».
4. Коммитьте после каждой проверенной задачи. Код просматривает человек — это требование безопасной разработки, а не формальность.
5. Если меняется решение — сначала ТЗ или ADR, потом код.

## Основной цикл

### Промпт 0. Знакомство и вопросы
```
Прочитай CLAUDE.md и docs/SPEC.md полностью. Код пока не пиши.

1. Перескажи в 10–15 пунктах, что мы строим, для кого первые пилоты (ТЗ, 1.6) и какие ограничения из-за будущей сертификации ты обязан соблюдать с первого коммита.
2. Объясни, как ты будешь работать с матрицей обнаружения (ТЗ, 5.16): как её строки связываются с тестами и чего нельзя обещать в интерфейсе.
3. Найди в ТЗ противоречия, пробелы и рискованные места, со ссылками на разделы.
4. Задай вопросы: сначала открытые из раздела 16, потом свои. Не больше 12, по убыванию важности. К каждому предложи вариант по умолчанию на случай, если я не отвечу.
```

### Промпт 1. План этапа 0
```
Мои ответы: <вставьте ответы>. Где ответа нет, бери свой вариант по умолчанию и отметь это.

1. Обнови docs/SPEC.md по ответам: в разделе 16 отметь закрытые вопросы, поправь затронутые разделы, добавь строку в историю версий.
2. Составь план этапа 0 (ТЗ, раздел 14) и сохрани его в docs/plans/stage-0.md. Задачи по 0,5–1 дню; для каждой — результат, файлы, проверки, документы из раздела 9, статус.
3. Отдельным списком — зависимости и инструменты, которые хочешь поставить: назначение, лицензия, почему не хватает стандартной библиотеки. Я подтвержу списком.

Жди моего подтверждения.
```

### Промпт 2. Выполнение задачи
```
Выполни задачу <номер> из docs/plans/stage-<N>.md. Работай по CLAUDE.md: тесты вместе с кодом (для строк матрицы — с ID строки в имени теста), make check перед завершением, обновление затронутых документов. Отметь статус задачи в плане.

В конце: что сделано, что мне проверить руками, что осталось.
```

### Продолжить работу (начало новой сессии)
```
Прочитай CLAUDE.md, docs/plans/stage-<N>.md и последние 15 коммитов. Кратко: на какой задаче мы остановились, что в ней осталось, есть ли незакоммиченные изменения. Предложи следующий шаг и жди подтверждения.
```

### Промпт 3. Закрыть этап и спланировать следующий
```
1. Проверь критерии приёмки этапа <N-1> (ТЗ, раздел 14) и покрытие матрицы 5.16 для этого этапа. Отчитайся списком: выполнено, не выполнено, что мешает.
2. Если этап закрыт, переходим к этапу <N>. Прочитай разделы ТЗ, на которые он ссылается, и посмотри текущее состояние кода.
3. Выпиши строки матрицы 5.16, которые реализуются на этапе <N>, и тест, который покроет каждую.
4. Составь план задач по 0,5–1 дню и сохрани его в docs/plans/stage-<N>.md.
5. Отдельно: нужные зависимости, решения с меткой [Решение] и ADR, риски.

Жди подтверждения.
```

## Работа в проекте
Порядок работы, выбор модели, защита от повторного выполнения и требования к документации — в `docs/plans/roadmap.md`. Модель для шага указана в дорожной карте и в заголовке промпта; переключение — `/model` в начале сессии. Промпты для параллельных потоков этапа 1 — в `docs/plans/parallel-stage-1.md`.

Экономия токенов:
- одна сессия — один шаг дорожной карты;
- читать только нужные разделы ТЗ и затрагиваемые пакеты;
- во время работы — тесты затронутых пакетов, `make check` — один раз перед коммитом;
- в чат — итоги проверок, а не логи; промежуточные сообщения — одной строкой; отчёт — до 10 строк.

### Инструкции проекта (вставить в настройки проекта)
```
Проект AISec: шлюз безопасности ИИ, сертификация ФСТЭК. Правила — CLAUDE.md в репозитории, порядок работы — docs/plans/roadmap.md, промпты — docs/PROMPTS.md (раздел «Работа в проекте»).
- Одна сессия — один шаг дорожной карты. Состояние — только в репозитории: статусы, журнал и «Открытые вопросы» в docs/plans/stage-<N>.md.
- Перед любыми изменениями — проверка от повторного выполнения (roadmap.md, «Защита от повторного выполнения»). Выполненную задачу не переделывать, взятую другой сессией — не трогать.
- Документация — часть готовности (roadmap.md, «Документация — часть готовности»): без обновлённых документов задача не готова.
- Go — с GOTOOLCHAIN=go1.27.2. make vuln в облачной среде падает с 403 — это известно, в CI проходит.
- Коммиты — Conventional Commits на русском с меткой «(задача N этапа M)» или «(ревью N–K этапа M)»; push в рабочую ветку; PR не создавать.
- Экономия: только нужные разделы ТЗ и пакеты; в чат — итоги проверок, не логи; промежуточные сообщения — одной строкой; отчёт — до 10 строк.
```

### P1. Статус — Haiku
```
Статус проекта, только чтение. git pull --ff-only. По docs/plans/roadmap.md и плану текущего этапа: последний выполненный шаг, задачи «в работе» (с датой), следующий шаг дорожной карты с промптом и моделью, вопросы из «Открытых вопросов», которые ждут меня. Ничего не меняй. До 8 строк.
```

### P2. Задача — модель по дорожной карте
```
Выполни шаг <шаг> дорожной карты: задачи <N>[, <N2>] этапа <M>.
1. Защита от повтора (roadmap.md): git pull --ff-only; статус в плане и метка «задача <N> этапа <M>» в git. Готова или в работе — остановись и сообщи.
2. Возьми задачу: статус «в работе (дата)», коммит docs, push. Push отклонён — pull и проверь снова.
3. Контекст — только строка задачи и решения этапа в плане, «Открытые вопросы», нужные разделы ТЗ через оглавление, затрагиваемые пакеты. auth, crypto, audit, integrity, сборка, зависимости — сначала короткий план и жди ответа.
4. Код и тесты по CLAUDE.md: ID строк матрицы в именах тестов, fuzz для разборщиков. Во время работы — тесты затронутых пакетов.
5. Документы — по списку «Документация — часть готовности».
6. make check один раз, в чат — итог. Коммит «… (задача <N> этапа <M>)» со статусом «готова» и строкой журнала; push. Две задачи — два коммита.
Отчёт до 10 строк: что сделано, коммит, обновлённые документы, что проверить руками, вопросы.
```

### P3. Ревью — Opus
```
Ревью шага <шаг>: cert-reviewer на диапазон <база>..HEAD (задачи <список> этапа <M>).
Защита от повтора: если в журнале плана уже есть «ревью <N>–<K>» — сообщи и остановись.
Передай ревьюеру итоги последнего make check: проверки не перезапускать, только чтение диффа и кода; не больше 15 замечаний.
Запиши замечания в «Открытые вопросы» плана: важные — с файлом, сутью, сценарием и исправлением; незначительные — строкой. Добавь строку журнала, коммит docs, push. Исправления — следующей сессией (P4). Отчёт до 8 строк.
```

### P4. Исправления по ревью — Opus
```
Исправь замечания ревью <N>–<K> этапа <M> из «Открытых вопросов» плана.
Защита от повтора: если в git есть коммит с меткой «ревью <N>–<K> этапа <M>» — сообщи и остановись.
Важные — все, незначительные — если правка в 1–2 строки; остальное оставь в разделе с пометкой. На каждый обход или отказ — тест.
Документы по списку готовности; метрики и бенчмарки — если изменились. make check один раз.
Коммит «fix: … (ревью <N>–<K> этапа <M>)», раздел и журнал обнови, push. Отчёт до 10 строк.
```

### P5. План этапа — Opus
```
Спланируй этап <N>: ТЗ, раздел 14, и разделы, на которые он ссылается; посмотри текущее состояние кода.
Защита от повтора: если docs/plans/stage-<N>.md уже есть — покажи его статус и остановись.
Задачи по 0,5–1 дню с колонками «Зависит от», «Модель» (по таблице выбора модели в roadmap.md) и «Статус»; строки матрицы 5.16 и тест на каждую; точки ревью; решения с меткой [Решение] и нужные ADR; новые библиотеки; риски.
Добавь шаги этапа в roadmap.md. Сохрани, коммит docs, push. Жди подтверждения перед задачами.
```

### P6. Закрытие этапа — Opus
```
Закрытие этапа <N>.
Защита от повтора: если в плане этапа отмечено «этап закрыт» — сообщи и остановись.
Проверь критерии приёмки (ТЗ, 14) и make dm-coverage при STAGE=<N>; все задачи «готова»; в «Открытых вопросах» нет важных незакрытых замечаний.
Отчёт списком: выполнено, не выполнено, что мешает. Если всё выполнено — отметь «этап закрыт (дата)» в плане, коммит docs, push.
```

### P7. Конец сессии — любая модель
```
Завершаем сессию. Если задача не закончена — статус оставь «в работе», в «Открытые вопросы» запиши, что сделано и что осталось (файлы, следующий шаг). Коммит, push. В ответе — 3 строки: где остановились, что дальше (шаг дорожной карты, промпт, модель), что ждёт моего решения.
```

