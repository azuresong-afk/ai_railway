# Промпты для Claude Code

## Как пользоваться
1. Создайте пустой репозиторий и положите в корень содержимое комплекта: `CLAUDE.md`, `docs/`, `.claude/` (скрытая папка с настройками и сабагентом). Сделайте первый коммит.
2. Запустите Claude Code в корне репозитория. Для промптов 0 и 1 включите режим планирования (Shift+Tab): Claude покажет план и ничего не будет менять.
3. Один этап — несколько сессий. Между крупными задачами очищайте контекст командой `/clear`: всё важное хранится в файлах, а не в истории чата.
4. Коммитьте после каждого проверенного шага. Код просматривает человек — это требование безопасной разработки, а не формальность.
5. Если меняется решение — сначала обновите ТЗ или ADR, потом код.

## Промпт 0. Знакомство и вопросы
```
Прочитай CLAUDE.md и docs/SPEC.md полностью. Код пока не пиши.
1. Перескажи в 10–15 пунктах, что мы строим и какие ограничения из-за сертификации ты обязан соблюдать.
2. Найди в ТЗ противоречия, пробелы и рискованные места, со ссылками на разделы.
3. Задай вопросы: сначала из раздела 16 ТЗ, потом свои. Не больше 12, по убыванию важности. К каждому предложи вариант по умолчанию на случай, если я не отвечу.
```

## Промпт 1. План этапа 0
```
Мои ответы: <вставьте ответы на вопросы>.
Обнови docs/SPEC.md по этим ответам (в разделе 16 отметь закрытые вопросы) и составь план этапа 0 (ТЗ, раздел 14).
План — задачи по 0,5–1 дню. Для каждой: результат, файлы, проверки, какие документы из раздела 9 затрагиваются.
Отдельным списком — зависимости и инструменты, которые хочешь поставить, с лицензиями. Я подтвержу списком.
Жди моего подтверждения.
```

## Промпт 2. Выполнение задачи
```
Выполни задачу <номер> из плана этапа <N>. Работай по CLAUDE.md: тесты вместе с кодом, make check перед завершением, обнови затронутые документы. В конце: что сделано, что мне проверить руками, что осталось.
```

## Промпт 3. План следующего этапа
```
Переходим к этапу <N> (ТЗ, раздел 14). Прочитай разделы ТЗ, на которые ссылается этап, и посмотри текущее состояние кода.
Составь план задач по 0,5–1 дню с тестами и документами. Отдельно — риски и вопросы, которые должен решить я. Жди подтверждения.
```

## Служебные промпты

### Ревью перед коммитом
```
Вызови сабагента cert-reviewer для изменений относительно <ветка или коммит>. Исправь замечания уровней «критично» и «важно», по остальным дай мне список.
```

### Нужна новая библиотека
```
Для <задача>, возможно, нужна библиотека. Не ставь её. Сравни реализацию на стандартной библиотеке с 2–3 кандидатами: лицензия, активность проекта, транзитивные зависимости, поверхность атаки. Дай рекомендацию.
```

### Дизайн-система (перед вёрсткой экранов)
```
Прочитай ТЗ, раздел 6.
1) Предложи уточнённые токены: цвета обеих тем, шрифт из двух кандидатов, типографическую шкалу, отступы, радиусы. Сверь их с брифом 6.1 и списком 6.10. Что получилось шаблонным — исправь и объясни, что поменял.
2) После моего подтверждения собери страницу /dev/ui-kit со всеми базовыми компонентами в обеих темах.
```

### Экран
```
Сверстай экран «<название>» по ТЗ 6.4 на компонентах из ui-kit. Данные — через API; если эндпоинта нет, сначала обнови api/openapi.yaml. Покрой основной сценарий e2e-тестом и проверь работу при CSP из 6.9.
```

### Изменилось решение
```
Мы решили: <решение>. Обнови docs/SPEC.md (назови разделы), оформи ADR и перечисли, какой код и документы это затрагивает. Код пока не меняй.
```

### Сверка с нормативкой (раз в квартал и перед сертификацией)
```
Проверь по актуальным источникам, не изменились ли документы из раздела 17 ТЗ: новые редакции приказов ФСТЭК и ФСБ, методик, статус проекта изменений в приказ № 117. Составь список расхождений с ТЗ и предложи правки. Ничего не меняй без подтверждения.
```

### Перед пилотом
```
Проверь готовность к пилоту у заказчика: установи продукт по руководству на чистую ВМ (если в твоём окружении это невозможно — пройди руководство и отметь неясные шаги), прогони сценарии S1–S4 и S8–S10 из ТЗ 1.4, сформируй отчёт «Итоги пилота» на демо-данных. Составь список проблем, которые заметит заказчик, по убыванию важности.
```

### Перед передачей в лабораторию
```
Проверь полноту артефактов из раздела 9 ТЗ: что отсутствует, что устарело относительно кода, где нет трассировки «функция безопасности → код → тест». Выдай отчёт списком.
```
