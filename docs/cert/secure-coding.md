# Правила безопасного кодирования

Черновик этапа 0. Основа — правила из `CLAUDE.md` плюс разделы по Go, TypeScript и SQL (ТЗ, 8.3). Всё, что можно проверить автоматически, проверяется автоматически.

## Общие правила
Источник — `CLAUDE.md`, раздел «Жёсткие правила». Кратко:
- **Зависимости** — только с явного согласия владельца, с записью в `components.yaml`; лицензии — по allowlist; версии фиксируются точно, Go-модули вендорятся.
- **Криптография** — только в `internal/crypto`, через криптопрофиль; собственных реализаций алгоритмов нет. Остальные пакеты получают готовые объекты.
- **Сеть** — только явно настроенные адреса; никакой телеметрии, проверки обновлений, CDN.
- **Логи** — без секретов, ключей, паролей, токенов, содержимого промптов. Содержимое запросов сохраняется только через модуль событий по режиму хранения.
- **Ввод и вывод** — у любого входа предел размера и проверка; SQL только параметризованный; у исходящего вызова есть контекст и таймаут.
- **Доступ и аудит** — у эндпоинта проверка прав и тест на отказ; действие администратора пишется в аудит.
- **Поверхность атаки** — изменился внешний интерфейс — обновить `attack-surface.md`; изменилась функция безопасности — `security-functions.md`.
- **Проверки не ослабляются** ради «зелёной» сборки; ложное срабатывание размечается с обоснованием.
- **Тестовые ПДн** — только синтетические.

## Go
- Без `unsafe`, без `reflect` в обход типов, без `os/exec` и `syscall` в серверных компонентах (исключение — `syscall.SIGTERM`, ADR-0004), без `math/rand` где бы то ни было, без `plugin`.
- Секреты сравниваются только за постоянное время (`crypto.Equal`, `MAC.Verify`).
- Ошибки не игнорируются. Если ошибка действительно не важна, это видно в коде: явная обработка или подавление с обоснованием.
- Тексты ошибок для пользователя — без внутренних подробностей. Тексты ошибок в журнале — без секретов и содержимого: например, вместо `*url.Error` целиком — класс ошибки.
- Типы с секретами не печатаются: `Format` и `LogValue` выводят только безопасное описание (пример — `hmacSHA256`).
- Входные данные читаются с пределом размера: `http.MaxBytesReader`, `io.LimitReader`. Проверки размера и типа делаются на уже открытом файле, а не по `os.Stat` перед открытием.
- HTTP-сервер — только через `internal/httpserver` (TLS, таймауты, лимит заголовков). HTTP-клиент — с транспортом без прокси из окружения, с таймаутами; запросы — с контекстом (`NewRequestWithContext`).
- Каждому разборщику входных данных — fuzz-тест (`go test -fuzz`), найденные падения коммитятся в `testdata/fuzz/`.
- Комментарии — на русском; идентификаторы — на английском.

## SQL
Применяется с этапа 2 (PostgreSQL через pgx).
- Только параметризованные запросы; склейка SQL из пользовательского ввода запрещена. Имена таблиц и колонок в динамических запросах — только из фиксированного списка в коде.
- Миграции — чистый SQL во встроенных файлах, у каждой есть план отката (ТЗ, ОБН.2).
- У каждой выборки предел строк, у каждого запроса — контекст с таймаутом.
- Права СУБД — минимальные; для журнала аудита — только добавление (РСБ.4).
- `rows.Close()` и `rows.Err()` проверяются (линтеры sqlclosecheck, rowserrcheck).

## TypeScript
Применяется с этапа 2 (веб-консоль). Заготовка правил:
- Строгий режим TypeScript; eslint с правилами безопасности — в `make check`.
- Без `dangerouslySetInnerHTML`, `eval`, `new Function`, `innerHTML`. Содержимое промптов и ответов выводится только как текст.
- Токены и сессии — не в `localStorage` и `sessionStorage`; сессия — cookie `HttpOnly`, `Secure`, `SameSite=Strict`.
- Шрифты, иконки и скрипты — только локально; интерфейс работает при строгом CSP из ТЗ, 6.9.
- npm-пакеты — только из lock-файла (`npm ci`), новые — по процедуре согласования зависимостей.

## Что проверяется автоматически
Конфигурация — `.golangci.yml`, запуск — `make lint`. Работу запретов доказывает `make lint-selftest`: образец `tools/lintcheck/testdata/sample` содержит заведомые нарушения с маркерами `// want:<линтер>` и разрешённые случаи с маркерами `// clean:<линтер>`; утилита `tools/lintcheck` запускает линтеры и сверяет замечания с маркерами. Если правило ослабить, самопроверка падает.

| Правило | Как проверяется |
|---|---|
| Криптография только в `internal/crypto` (`crypto/*`, `golang.org/x/crypto/*`) | depguard, правило `crypto`; действует и в тестах, и в `tools/`. Каталог `internal/crypto` в модуле ровно один — `./internal/crypto` (`make repocheck`), иначе вложенный `…/internal/crypto` снял бы запрет. Утилиты проверки пропускают `vendor/`, `build/`, `bin/`, `node_modules/` только в корне репозитория, а `testdata/` — на любой глубине: вложенный каталог с таким именем Go собирает, и пропуск открыл бы обход |
| Без `unsafe`, `math/rand` (в том числе `math/rand/v2`), `net/http/pprof`, `plugin` | depguard, правило `unsafe-and-rand`; во всём коде |
| Без `os/exec` в серверных компонентах | depguard, правило `server-exec`: `cmd/aisec-gateway`, `cmd/aisec-server`, `cmd/aisec-media`, `internal/`; там же запрещён `syscall`. Единственное исключение — `syscall.SIGTERM` в файле `signal.go` команды (ADR-0004); forbidigo во всём коде запрещает любые `syscall.*`, кроме `SIGTERM`. Обходы через `os.StartProcess` и `syscall.Exec`/`ForkExec`/`StartProcess` ловит forbidigo во всём коде |
| Без `reflect` в обход типов | depguard, правило `product-reflect`: `cmd/aisec-gateway`, `cmd/aisec-server`, `cmd/aisec-media`, `internal/` кроме тестов; исключение — `//nolint:depguard` с обоснованием |
| cgo — только по ADR | `make repocheck`: файлы с `import "C"` разрешены только в путях из `CGO_ALLOWED` в `Makefile` (сейчас пусто). `make lint` и `make vet` идут с `CGO_ENABLED=1`, чтобы линтеры видели и файлы с cgo |
| Технические логи только через `log/slog`; без `print`, `fmt.Print*`, `log.Print*` | forbidigo с анализом типов: псевдоним импорта (`import f "fmt"`) запрет не обходит |
| Исходящие HTTP-запросы с контекстом | noctx |
| Ошибки проверяются | errcheck, errorlint, nilerr, gosec G104 |
| Закрытие тел ответов, строк и выражений SQL | bodyclose, rowserrcheck, sqlclosecheck |
| Проверки безопасности | gosec в режиме аудита — только в `make sast` (срабатывания размечаются в `docs/cert/sast-triage/`); `make sast` входит в `make check` |
| Каждое подавление — с линтером и обоснованием | nolintlint (`require-specific`, `require-explanation`) |
| Срабатывания SAST размечены | `make sast`: gosec в SARIF, сверка с `docs/cert/sast-triage/triage.yaml`, перечень подавлений `//nolint:gosec` (формат — `docs/cert/sast-triage/README.md`) |
| Форматирование | gofmt (`make fmt-check` и форматтер в golangci-lint) |

Самопроверка сверяет только размеченные строки: неразмеченные замечания в образце не считаются ошибкой. Образец собирается без сети (`GOPROXY=off`, `-mod=readonly`), а `golang.org/x/crypto` в нём подменён локальной заглушкой.

Замечания не схлопываются по строке (`uniq-by-line: false`): иначе одно замечание скрывает другое на той же строке — это было обнаружено самопроверкой.

## Чек-лист ревью
Каждое изменение просматривает человек, даже если код написал ИИ-ассистент (ТЗ, 8.10). Предварительно — сабагент `cert-reviewer`. Владелец проверяет:

1. **Задача.** Изменение делает то, что описано в плане, и не больше. Рефакторинг не смешан с новой функциональностью.
2. **`make check`** зелёный в CI, новых подавлений без обоснования нет.
3. **Зависимости.** Новых нет, или они согласованы и внесены в `components.yaml`.
4. **Криптография.** Только через `internal/crypto`; новых алгоритмов и режимов нет без решения.
5. **Входные данные.** У нового входа предел размера, проверка формата, fuzz-тест.
6. **Сеть.** Новых исходящих соединений нет, или адрес задаёт администратор; у вызовов есть таймауты.
7. **Логи и ошибки.** Нет секретов, ключей, содержимого запросов; тексты для пользователя без подробностей.
8. **Доступ и аудит** (с этапа 2). У эндпоинта проверка прав и тест на отказ; действие администратора пишется в аудит.
9. **Тесты.** Есть позитивные, негативные и граничные случаи; тест матрицы назван с ID строки (`TestDMNN_…`).
10. **Документы.** Обновлены `attack-surface.md`, `security-functions.md`, `api/openapi.yaml`, ADR — если изменение их касается.
11. **Разметка SAST.** Новые записи в `triage.yaml` проверены по коду: обоснование верное. Неверно размеченных ложных срабатываний должно быть не больше 10 % (ТЗ, 8.1).
