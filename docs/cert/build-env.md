Черновик этапа 0. Описание сборочной среды для проверки по методике ФСТЭК, включая использование ИИ-ассистента (ТЗ, 8.7, 8.11).

## Инструменты
Инструменты разработки не входят в поставку и не попадают в SBOM продукта; они учитываются в `docs/cert/components.yaml` с `scope: build` (решение Д5 плана этапа 0). Версии зафиксированы в начале `Makefile`, установка — `make tools` в `bin/`.

| Инструмент | Версия | Лицензия | Назначение |
|---|---|---|---|
| Go toolchain | 1.27.1 | BSD-3-Clause | Сборка, тесты, фаззинг, `go vet`, `gofmt` |
| golangci-lint | v2.14.0 | GPL-3.0 | Линтеры и depguard. Отдельная программа сборочной среды: не линкуется в продукт и не поставляется (решение Д1) |
| govulncheck (`golang.org/x/vuln`) | v1.8.0 | BSD-3-Clause | Уязвимости зависимостей |
| sbom-utility | v1.0.1 | Apache-2.0 | Проверка SBOM по схеме CycloneDX |
| GNU Make | из сборочного образа | GPL-3.0 | Запуск целей сборки |

## Цели Makefile
Вся логика сборки и проверок — в `Makefile` (ТЗ, 11.4); список — `make help`. `make check` — всё, что нужно для pull request; состав растёт по мере выполнения задач этапа 0, а цели, которые ещё не реализованы, падают с сообщением, а не проходят молча.

Переменные окружения, которые задаёт Makefile:
| Переменная | Значение по умолчанию | Зачем |
|---|---|---|
| `GOTOOLCHAIN` | `local` | Запрет скрытой загрузки toolchain; нужен установленный Go 1.27 |
| `GOFLAGS` | `-mod=vendor` | Зависимости только из `vendor/` |
| `CGO_ENABLED` | `0` | Статические бинарники без cgo; для `make test` включается только ради детектора гонок (`-race`) |

Сборка: `go build -trimpath -ldflags '-s -w -buildid= …'`, результат в `build/bin/`. Инструменты разработки ставятся `make tools` в `bin/` по версиям из переменных в начале `Makefile`.
