# Разметка срабатываний статического анализа

SARIF — артефакт CI; в репозитории хранятся разметка срабатываний (`triage.yaml`) и снимки SARIF к релизам (ТЗ, 8.4). По методике ФСТЭК лаборатория может переиспользовать результаты разработчика, если неверно размеченных ложных срабатываний в контрольной выборке не больше 10 % (ТЗ, 8.1), поэтому каждое обоснование должно проверяться по коду.

## Как работает проверка
`make sast`:
1. golangci-lint с одним gosec пишет `build/sast/gosec.sarif`.
2. `tools/sast-triage` сверяет каждое срабатывание с `triage.yaml`:
   - не размечено — ошибка;
   - размечено как истинное (`true_positive`) — ошибка: истинное срабатывание исправляется, а не размечается;
   - размечено как ложное (`false_positive`) с обоснованием — проходит;
   - запись разметки без срабатывания — предупреждение: запись устарела, её нужно удалить.
3. Подавления `//nolint:gosec` в коде выписываются в `build/sast/suppressed.md`. Это тоже решения по срабатываниям: каждое содержит обоснование (правило nolintlint), и лаборатория видит их вместе с разметкой.

Отпечаток срабатывания — правило, файл и текст строки кода без пробелов по краям. Номер строки в отпечаток не входит, чтобы правки выше по файлу не сбрасывали разметку. Если строка с размеченным срабатыванием изменилась, разметку нужно пересмотреть.

Следствие: одна запись покрывает все одинаковые строки файла с тем же правилом, в том числе будущие копии этой строки. Если одинаковые строки требуют разных решений, строку нужно сделать различимой (например, вынести в функцию). Повторяющиеся записи разметки — ошибка.

gosec запускается только в `make sast`, а не в общем `make lint`: так срабатывание можно разметить здесь, не подавляя его в коде. `make sast` входит в `make check`, поэтому проверка не ослабляется. Подавление `//nolint:gosec` в коде тоже допустимо, но только с обоснованием, и оно попадает в перечень `suppressed.md`.

## Формат разметки
```yaml
schema_version: 1
entries:
  - rule: gosec/G304            # ruleId из SARIF и код проверки gosec
    file: tools/x/main.go       # путь от корня репозитория
    snippet: "data, err := os.ReadFile(p)"   # строка кода без пробелов по краям
    verdict: false_positive     # false_positive или true_positive
    justification: Путь получен обходом каталога репозитория, а не из внешнего ввода.
    author: Фамилия И. О.
    date: 2026-09-29            # ГГГГ-ММ-ДД
```

## Как размечать
- Обоснование объясняет, почему срабатывание ложное именно в этом месте, со ссылкой на код, который это гарантирует, а не «так задумано».
- Если сомневаетесь, считайте срабатывание истинным и исправляйте.
- Разметку проверяет владелец при ревью pull request, как код.

## Снимки к релизам
К каждому релизу `build/sast/gosec.sarif` и `build/sast/suppressed.md` копируются в `releases/<версия>/` этого каталога.
