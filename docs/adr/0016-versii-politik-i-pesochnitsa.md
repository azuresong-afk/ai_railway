# ADR-0016. Хранение версий политик и песочница на конвейере шлюза

- Статус: предложено
- Дата: 21.10.2026
- Связанные разделы ТЗ: 5.3, 5.16 (DM-14, DM-40), 7.3 (УПД.2, РСБ.1, РСБ.3, ОЦЛ.3); задача 2.12 этапа 2

## Контекст
В этапе 1 политики жили только в файле конфигурации шлюза. Консоли нужны версии с откатом и сравнением, загрузка и выгрузка YAML и песочница, которая проверяет текст без обращения к модели. Версия политики станет содержимым подписанного пакета для шлюзов (задача 2.13), поэтому её байты должны быть однозначными и неизменными. Ограничения: новых зависимостей нет, SQL только параметризованный, драйвер PostgreSQL не должен попасть в бинарник шлюза, содержимое проверяемого текста не попадает в журналы.

## Решение
1. **Отдельный пакет** `internal/policy/versions` (`Service`, `Store`, `Memory`, `PGStore`) по образцу `internal/apps`. Пакет `internal/policy` остаётся без БД: его импортирует шлюз.
2. **Версия неизменяема и хранится каноничным YAML** (`policy.Marshal`) с хешем криптопрофиля и алгоритмом. Номер версии внутри YAML ставит сервер. Пустые `non_text` и `response_check` записываются явно: смысл сохранённой версии не меняется, если позже сменятся умолчания. Из консоли и API пустой `non_text` — `allow_inline` (решение по 1.19), при загрузке YAML — `allow_unchecked`, как файл понимал шлюз этапа 1.
3. **Изменение — новая версия поверх `base_version`** под блокировкой строки политики; устаревшая версия — 409. Откат — новая версия с содержимым старой и отметкой `rolled_back_from`.
4. **Гарантии в БД** (миграция `0017_policies`): триггер `policy_versions_guard` запрещает `UPDATE` и `DELETE` версий всем, включая владельца схемы, и требует номер max+1; триггер `policies_guard` запрещает удаление политики и смену ID, организации и сведений о создании, текущая версия растёт ровно на 1; отложенный внешний ключ — текущая версия существует. У `aisec_app` на версии только `SELECT, INSERT`.
5. **Аудит в той же транзакции** со сводкой изменений (имена полей, ID правил) и признаком `weakening` с причинами — основа правила DM-40 этапа 3. Содержимое правил и сообщений в запись не пишется.
6. **Категории `lists.*` при сохранении принимаются любые**: словари задаёт приложение, а политика с ним не связана. Остальные категории проверяются строго. Связь со словарями приложения проверяют песочница и сборка пакета (2.13).
7. **Песочница вызывает конвейер шлюза в процессе сервера**: новый файл `internal/gateway/sandbox.go` экспортирует `Sandbox` — обёртку над `App.inspect` с `endpoint=check`, без событий, квот, псевдонимов пользователя и провайдера. Вход — тело запроса Check API как есть, его разбирает тот же `parseCheck`. Остальной код шлюза не меняется.
8. **Права**: `policies.read`; `policies.manage` с признаком безопасности (только администратор безопасности, токенам не выдаётся, УПД.2); отдельное `policies.test` для песочницы — она ничего не меняет.

## Альтернативы
- Хранить политику строками правил в таблицах. Отклонено: пакету для шлюзов (2.13) нужен один подписываемый документ, а сравнение по YAML-байтам и по структуре проще на канонической записи.
- Копия конвейера проверки в сервере. Отклонена: песочница и шлюз со временем разошлись бы, администратор проверял бы одно, а шлюз делал другое.
- Песочница через запрос к работающему шлюзу. Отклонена: нужен ключ приложения и событие `check` с содержимым, а шлюза может не быть.
- Изменение версии на месте с журналом изменений. Отклонено: ТЗ 5.3 требует неизменяемых версий, а пакет 2.13 ссылается на версию по хешу.
- Последний записавший побеждает (без `base_version`). Отклонено: молчаливая потеря чужой правки политики безопасности.

## Последствия
- Бинарник сервера включает пакет шлюза (`internal/gateway`, провайдеры не вызываются); бинарник шлюза драйвер PostgreSQL не получает.
- Удаления и архивации политик нет: на них ссылаются приложения и пакеты. Неиспользуемая политика остаётся в списке.
- Политика, которую нельзя скомпилировать для приложения (нет словаря `lists`), сохраняется, но песочница с этим приложением отвечает 422, а пакет 2.13 её не соберёт.
- Затронуты `docs/cert/security-functions.md`, `attack-surface.md`, `threat-model.md`, `fuzzing.md`, `rbac-matrix.md`, `api/openapi.yaml`, ТЗ 5.3, 5.4 и DM-14.
- Откат: удалить маршруты и пакет; таблицы удаляются новой миграцией (версии триггер удалять не даёт — это намеренно, удаление только сменой схемы).
