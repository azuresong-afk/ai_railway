# ADR-0011. Инструменты фронтенда и лицензии npm

- Статус: принято
- Дата: 20.10.2026
- Связанные разделы ТЗ: 6.9, 8.6, 8.7, 11.2; `CLAUDE.md`, «Зависимости», «Фронтенд»; ADR-0003, п. 5; план этапа 2, решение Р12

## Контекст
1. Веб-консоль на TypeScript и React собирается из npm-пакетов. Список прямых зависимостей одобрен ТЗ 11.2; полное дерево — 331 пакет (в поставку статикой попадают только пакеты, достижимые из `dependencies`).
2. `CLAUDE.md` разрешает MIT, BSD-2/3, Apache-2.0, ISC, OFL; MPL-2.0 — только отдельным решением. В дереве сборки есть пакеты с другими лицензиями: `lightningcss` (MPL-2.0) нужен и Vite 8, и Tailwind CSS 4; ещё `tslib` (0BSD), `minimatch` (BlueOak-1.0.0), `@csstools/*` (MIT-0), `mdn-data` (CC0-1.0), `caniuse-lite` (CC-BY-4.0, данные), `argparse` (Python-2.0).
3. Сборка должна быть воспроизводимой и без скрытых загрузок (ADR-0003, п. 2, 5; ТЗ 8.7).

## Решение
1. **Lock-файл — источник состава.** `web/package-lock.json` (lockfileVersion 3) закоммичен; установка — только `npm ci --ignore-scripts` с проверкой `integrity` (`make web-deps`; без сети — `make web-deps-offline` из кэша npm). Версии прямых зависимостей в `package.json` точные, без диапазонов. Источник пакетов — только `https://registry.npmjs.org/`.
2. **Лицензии сборочной среды (решение владельца, 20.10.2026).** Для пакетов, достижимых только из `devDependencies` (не попадают в поставку), дополнительно допускаются MPL-2.0, 0BSD, MIT-0, BlueOak-1.0.0, CC0-1.0, CC-BY-4.0 (данные), Python-2.0. MPL-2.0 — исключение из `CLAUDE.md`; обоснование: код `lightningcss` в продукт не входит и не изменяется, его нельзя исключить без перехода на устаревшие ветки Vite 7 и Tailwind CSS 3.4. Список — `components.NPMBuildLicenses` в `tools/internal/components`.
3. **Лицензии поставки.** Пакеты, достижимые из `dependencies`, — только по политике `CLAUDE.md`. Исключение требует записи в `docs/cert/components.yaml` с `license_decision`.
4. **Проверки.** `make licenses` сверяет `package.json` и `package-lock.json` с реестром (прямые зависимости: версия, область, лицензия; поставка — `product`, сборка — `build`), проверяет источник, `integrity` и лицензию каждого из 331 пакета. `make sbom` включает в SBOM все npm-пакеты поставки (purl `pkg:npm/…`, SHA-512 из `integrity`, свойства `GOST:*`; транзитивным они передаются от прямой зависимости). Транзитивные пакеты в реестр по одному не вносятся.
5. **`tslib` (0BSD) в поставке.** Транзитивная зависимость `echarts`, входит в поставку. Владелец подтвердил исключение 21.10.2026; оформлено записью в реестре с `license_decision`.
6. **Запреты фронтенда — правилами eslint**, а не соглашением: `dangerouslySetInnerHTML`, `innerHTML`/`outerHTML`/`insertAdjacentHTML`, `document.write`, `eval`, `new Function`, строки в `setTimeout`, `localStorage`/`sessionStorage`, абсолютные URL; плюс `eslint-plugin-security`. Тест `web/src/lint-rules.test.ts` проверяет, что каждый запрет срабатывает. Плагин `eslint-plugin-no-unsanitized` (MPL-2.0) не используется.
7. **Статика в бинарнике.** Пакет `web` (`web/embed.go`) встраивает `web/dist` через `go:embed`; в репозитории лежит только `web/dist/.gitkeep`, поэтому `go build` работает и без Node. `aisec-server` подключает пакет, раздача статики и CSP-заголовок — в задачах каркаса консоли. Включение в манифест целостности — задача 2.17.
8. **Строгий CSP.** Сборка не создаёт встроенных скриптов и стилей (`modulePreload.polyfill: false`, `assetsInlineLimit: 0`, CSS — отдельным файлом); e2e-тест Playwright открывает консоль при CSP из ТЗ 6.9 и проверяет отсутствие нарушений и внешних запросов.
9. **Playwright не скачивает браузеры**: скрипты установки отключены; браузер — из `PLAYWRIGHT_BROWSERS_PATH` сборочного образа либо `AISEC_CHROMIUM`.
10. **Версии.** TypeScript 5.9.3, а не 7: `typescript-eslint` и `openapi-typescript` его пока не поддерживают.

## Альтернативы
- **Vite 7 + Tailwind CSS 3.4 без `lightningcss`** — отклонено: старые ветки, меньше срок поддержки, исключение лишь переносится на другие пакеты.
- **Вносить в реестр все 331 пакета** — отклонено: сотни записей вручную без пользы; проверка по lock-файлу строже и не устаревает.
- **Вендорить `node_modules` в репозиторий** — отклонено: десятки тысяч файлов; `integrity` в lock-файле и кэш npm в сборочном образе решают задачу.
- **`eslint-plugin-no-unsanitized`** — отклонён из-за MPL-2.0; запреты заданы встроенными правилами eslint.

## Последствия
- `make check` включает `web-check` и `web-e2e`, когда на машине есть `npm`; иначе они печатаются как невыполненные (сборочный образ ещё без Node.js — задача образа и CI вне этой задачи).
- Обновление зависимости: `npm install` в `web/`, правка записи в `components.yaml` (версия, лицензия), `make licenses`.
- Откат: удалить `web/`-инструменты и запись `npm-package` из реестра; Go-часть (`tools/internal/npmlock`) без lock-файла ничего не делает.
- Переход на внутреннее зеркало npm — к этапу 6 (ADR-0003, п. 5).
