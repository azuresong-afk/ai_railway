# ADR-0001. Стек и базовые зависимости

- Статус: принято
- Дата: 29.09.2026
- Связанные разделы ТЗ: 4, 8.6, 10.2, 11.1, 11.2, 14 (этап 0)

## Контекст
Продукт идёт на сертификацию ФСТЭК (уровень доверия 4). Каждый заимствованный компонент нужно учитывать в SBOM, проверять на уязвимости и поддерживать весь срок техподдержки; лаборатория анализирует и его код. Значит, чем меньше зависимостей и чем проще их граф, тем дешевле сертификация. Одновременно нужна производительность прокси с потоковой передачей (ТЗ, 5.1) и работа в закрытом контуре.

## Решение
- **Backend:** Go, версия `go 1.27.0`, toolchain `go1.27.1` (последний стабильный выпуск на дату решения) — фиксируется в `go.mod`. В первую очередь стандартная библиотека: `net/http` и `net/http/httputil` (сервер, маршрутизация через `ServeMux`, обратный прокси), `log/slog` (JSON-логи), `testing` (тесты, фаззинг), `debug/buildinfo` (SBOM).
- **Сборка:** `CGO_ENABLED=0`, `-trimpath`, статические бинарники. cgo — только в `aisec-media` и только по отдельному ADR.
- **Хранилище:** PostgreSQL 15+ через `github.com/jackc/pgx/v5` (этап 2), только возможности ядра и contrib; миграции — собственный исполнитель встроенных SQL-файлов.
- **YAML:** `go.yaml.in/yaml/v3` — продолжение `gopkg.in/yaml.v3` под сопровождением организации YAML (исходный репозиторий с апреля 2025 г. помечен как несопровождаемый). Лицензия `MIT AND Apache-2.0`, собственных зависимостей нет.
- **UUIDv7:** собственная реализация по RFC 9562; случайная часть — из `Random` в `internal/crypto`. `github.com/google/uuid` не используется.
- **Криптография:** стандартная библиотека Go и `golang.org/x/crypto` — только внутри `internal/crypto` (ТЗ, 10.2).
- **Frontend:** TypeScript, React, Vite, Tailwind CSS, Radix UI, TanStack, ECharts (ТЗ, 11.2). Инструменты подключаются первой задачей этапа 2, когда появляется код консоли; до этого `web/` — заготовка, а `make check` проверяет только Go.
- Любая новая зависимость — по процедуре `CLAUDE.md` с записью в `docs/cert/components.yaml`.

## Альтернативы
- **Rust** для шлюза: выше порог входа и меньше поддержка сертифицированными анализаторами (Svace поддерживает Go).
- **Веб-фреймворки Go** (chi, echo, gin): `ServeMux` с Go 1.22 поддерживает методы и шаблоны путей, этого достаточно; фреймворк — лишний заимствованный код.
- **`gopkg.in/yaml.v3`:** не сопровождается, исправления уязвимостей не гарантированы.
- **`github.com/google/uuid`:** UUIDv7 — около 30 строк, а собственная реализация берёт случайность из криптопрофиля, как требует ТЗ.

## Последствия
- В `go.mod` продукта на этапе 0 одна библиотека — `go.yaml.in/yaml/v3`.
- Go toolchain и стандартная библиотека — тоже заимствованный компонент и учитываются в `components.yaml`.
- Обновление Go — плановая работа по процедуре обновления зависимостей (ТЗ, 8.6); версия поддерживается в `go.mod`, сборочном образе и CI одновременно.
