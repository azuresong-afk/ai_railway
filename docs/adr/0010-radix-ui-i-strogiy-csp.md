# ADR-0010. Radix UI при строгом CSP

- Статус: принято (замены ниже — на подтверждение владельца при ревью)
- Дата: 21.10.2026
- Связанные разделы ТЗ: 6.4, 6.9, 11.2; план этапа 2, решение Р13, задача 2.22; ADR-0011

## Контекст
ТЗ 6.9 требует, чтобы интерфейс работал при `style-src 'self'` (без `'unsafe-inline'`), и прямо просит проверить Radix UI макетом до вёрстки. Макет — `web/src/dev/RadixMockup.tsx` (адрес `#/dev/radix`), проверка — `web/e2e/radix.spec.ts` (Playwright, Chromium, заголовок CSP из ТЗ 6.9). Тест падает на любом нарушении CSP (`securitypolicyviolation`), ошибке или предупреждении консоли и на любом элементе `<style>` в разметке.

Результат проверки 14 примитивов (Radix UI, версии в `web/package.json`):

| Примитив | Результат | Причина |
|---|---|---|
| dialog, alert-dialog, dropdown-menu | не работает как есть | модальный режим подключает `react-remove-scroll`, он вставляет `<style>` (блокировка прокрутки) |
| select | не работает как есть | то же, плюс `SelectViewport` сам вставляет `<style>` для скрытия полосы прокрутки |
| scroll-area | не работает | `ScrollArea.Viewport` всегда вставляет `<style>` |
| popover, tooltip, tabs, checkbox, switch, radio-group, collapsible, label, toast | работает | нарушений нет; позиционирование идёт через CSSOM (`element.style.x = …`), его CSP не блокирует |

## Решение
1. **dialog, alert-dialog, dropdown-menu** остаются в модальном режиме. `react-remove-scroll` подменяется алиасом Vite на `web/src/shims/remove-scroll.tsx`: блокировка прокрутки — атрибут `data-scroll-locked` на `body` со счётчиком вложенных блокировок, правило `body[data-scroll-locked] { overflow: hidden }` лежит в `index.css`. Фокус-ловушка и `aria-hidden` для остального документа остаются от Radix. Модульный тест — `remove-scroll.test.tsx`.
2. **select** не используется: в консоли — родной `<select>` (доступен, без `<style>`). Если понадобится поиск в списке, делаем поле поиска с выпадающим списком на `popover`.
3. **scroll-area** не используется: нативная прокрутка (`overflow: auto`), полосы стилизуются CSS. Таблицы событий прокручивает TanStack Virtual.
4. Пакеты `@radix-ui/react-select` и `@radix-ui/react-scroll-area` в зависимости не включены. Остальные 12 записаны в `docs/cert/components.yaml`.
5. CSP не ослабляется ни для макета, ни для продукта: `'unsafe-inline'` и nonce в `style-src` не вводятся. Новый примитив Radix или иная библиотека с вставкой `<style>` добавляются в макет и e2e до использования в экранах.

## Альтернативы
- **`style-src 'unsafe-inline'`** — отклонено: нарушает ТЗ 6.9 и снимает защиту от внедрения стилей.
- **nonce для стилей**: статика встроена в бинарник и отдаётся без шаблонизации, nonce на каждый ответ усложняет раздачу и кэш; Radix поддерживает nonce не во всех местах. Не исключено позже, но не нужно, пока хватает замен.
- **`modal={false}` у диалогов** — отклонено: пропадают оверлей и перехват фокуса, для подтверждающих диалогов безопасности это хуже.
- **Другая библиотека примитивов (React Aria и др.)** — отклонено: новая зависимость и перестройка стека ради двух мест.

## Последствия
- Алиас подменяет стороннюю транзитивную библиотеку собственным кодом (~50 строк, в `internal/crypto` не относится). При обновлении Radix проверять, что он использует из `react-remove-scroll` только `RemoveScroll` с параметрами `as`, `allowPinchZoom`, `shards`; e2e и модульный тест это ловят.
- Не повторяется компенсация ширины полосы прокрутки при блокировке (при открытии диалога содержимое может сдвинуться на ширину полосы) — косметика, решается на этапе дизайн-системы (2.23).
- Откат: убрать алиас и шим, оставить модальные примитивы только при ослаблении CSP (ADR-ом).
