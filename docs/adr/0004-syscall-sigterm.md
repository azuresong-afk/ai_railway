# ADR-0004. Исключение для syscall.SIGTERM в серверных компонентах

- Статус: принято
- Дата: 01.10.2026
- Связанные разделы ТЗ: 4.4 (корректное завершение), 8.3; `CLAUDE.md`, «Go»

## Контекст
В серверных компонентах (`cmd/aisec-gateway`, `cmd/aisec-server`, `cmd/aisec-media`, `internal/`) пакет `syscall` запрещён правилом depguard: прямые системные вызовы — лишняя поверхность атаки. Но для корректного завершения по сигналу оркестратора (docker, systemd, Kubernetes присылают SIGTERM) нужна константа `syscall.SIGTERM`: в пакете `os` есть только `os.Interrupt` и `os.Kill`.

## Решение
- Импорт `syscall` разрешён только в отдельном файле `signal.go` команды, с `//nolint:depguard` и ссылкой на этот ADR. В файле — только функция, которая возвращает контекст, отменяемый по SIGINT и SIGTERM.
- Правило forbidigo во всём коде запрещает любые идентификаторы `syscall.*`, кроме `syscall.SIGTERM`. Поэтому открытый в файле импорт не даёт обойти запрет: любой другой вызов ловится линтером.
- Работу правила доказывает `make lint-selftest` (образец `tools/lintcheck/testdata/sample/cmd/aisec-server/signal.go`).

## Альтернативы
- **`golang.org/x/sys/unix`** — новая зависимость ради одной константы.
- **Только `os.Interrupt`** — оркестраторы останавливают процесс сигналом SIGTERM; без его обработки активные запросы обрывались бы.
- **`//nolint:depguard` прямо в `main.go`** — открывает весь пакет `syscall` для основного кода команды; отклонено после ревью.

## Последствия
- Каждой новой серверной команде нужен такой же `signal.go`.
- Другие системные вызовы (например, для изоляции `aisec-media`, ЗИ.7) — только отдельным ADR.

## Дополнение (22.10.2026, задача 3.7 этапа 3)
Ловушка сети `test/e2e/netwatch` для e2e пилота «без интернета» открывает сокет AF_PACKET (`syscall.Socket`): в пакете `net` таких сокетов нет. Это тестовый инструмент вне поставки: он не входит в образы и манифест, запускается только наложением `test/e2e/testdata/pilot/compose.e2e.yaml`. Разрешён один вызов `syscall.Socket` в `packetSocket` с `//nolint:forbidigo` и ссылкой на это дополнение; чтение — через `os.File`, константы протоколов — свои. Правило forbidigo и depguard для компонентов продукта не меняются.
