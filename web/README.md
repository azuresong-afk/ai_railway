# Веб-консоль

Каркас инструментов фронтенда (задача 2.21 этапа 2, [ADR-0011](../docs/adr/0011-instrumenty-frontenda.md)): TypeScript, React, Vite, Tailwind CSS, ESLint с плагином безопасности, Vitest, Playwright. Дизайн-система — задача 2.23, каркас консоли и вход — задача 2.24, экраны разделов — задачи 2.25–2.27.

## Требования
Node.js ≥ 22.12 и npm. Зависимости ставятся только из `package-lock.json`, без скриптов установки и без `audit`, `fund`, проверки обновлений (`.npmrc`). Источник пакетов — только `registry.npmjs.org`.

## Команды (из корня репозитория)
| Цель | Что делает |
|---|---|
| `make web-deps` | `npm ci --ignore-scripts` по lock-файлу (сеть или кэш npm) |
| `make web-deps-offline` | то же без сети, только из кэша npm |
| `make web-lint` | ESLint: запреты `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `new Function`, `localStorage`/`sessionStorage`, абсолютных URL |
| `make web-typecheck`, `make web-test` | типы (`tsc`) и модульные тесты (Vitest) |
| `make web-api-types` / `web-api-check` | типы из `api/openapi.yaml` в `src/api/schema.d.ts` / проверка, что они не устарели |
| `make web-build` | статика в `web/dist` (встраивается в `aisec-server` при `go build`, пакет `web`) |
| `make web-e2e` | Playwright: консоль в Chromium при строгом CSP (ТЗ, 6.9) |
| `make web-check` | всё выше, кроме e2e |

`make check` включает `web-check` и `web-e2e`, если на машине есть `npm`; без него они выводятся как невыполненные.

## Правила
- Новый npm-пакет — только с согласия владельца и записью в `docs/cert/components.yaml` (`type: npm-package`, точная версия). `make licenses` сверяет `package.json`, lock-файл и реестр и проверяет лицензии всех пакетов.
- Лицензии: пакеты поставки (достижимые из `dependencies`) — MIT, BSD-2/3, Apache-2.0, ISC, OFL. Для пакетов только сборочной среды (`devDependencies`) по решению владельца от 20.10.2026 допускаются ещё MPL-2.0 (`lightningcss`, нужен Vite 8 и Tailwind 4), 0BSD, MIT-0, BlueOak-1.0.0, CC0-1.0, CC-BY-4.0 (данные), Python-2.0. Исключение: 0BSD у `tslib` (зависимость `echarts`, в поставке) подтверждено владельцем 21.10.2026.
- Никаких CDN, внешних шрифтов, скриптов и стилей; шрифты и иконки — локально. Сборка не создаёт встроенных скриптов и стилей, интерфейс работает при CSP без `'unsafe-inline'`.
- Playwright не скачивает браузеры. Браузер берётся из `PLAYWRIGHT_BROWSERS_PATH` сборочного образа; путь к исполняемому файлу можно задать `AISEC_CHROMIUM`.
- `src/api/schema.d.ts` генерируется, руками не правится.

## Radix UI и строгий CSP (задача 2.22, [ADR-0010](../docs/adr/0010-radix-ui-i-strogiy-csp.md))
Макет всех нужных примитивов — `#/dev/radix`, проверка — `e2e/radix.spec.ts` (падает на любом нарушении CSP, ошибке консоли и элементе `<style>`).
- Работают как есть: `popover`, `tooltip`, `tabs`, `checkbox`, `switch`, `radio-group`, `collapsible`, `label`, `toast`.
- Работают через замену `react-remove-scroll` (алиас в `vite.config.ts`, `src/shims/remove-scroll.tsx`): `dialog`, `alert-dialog`, `dropdown-menu`.
- Не используются (вставляют `<style>`): `select` — вместо него родной `<select>`; `scroll-area` — нативная прокрутка.
- Новый примитив Radix сначала добавляется в макет и e2e.

## Дизайн-система (задача 2.23, ТЗ 6.2 и 6.10)
- **Токены** — `src/design/tokens.css` (цвета обеих тем, шкала 12/13/14/16/20/24/32 px, радиусы 4 и 8 px, тень только у всплывающих слоёв, плотность, длительности анимации). В Tailwind доступны как `bg-surface`, `text-muted`, `border-line`, `text-sev-critical`, `rounded-panel` и др. (`src/index.css`, `@theme inline`). Тема — атрибут `data-theme` на `<html>` (без него — по `prefers-color-scheme`), плотность — `data-density` (`compact` по умолчанию, `comfortable`). Выбор пользователя нельзя хранить в `localStorage`; сохранение — задача экрана настроек.
- **Серьёзность** — один набор цветов на обе темы (значок ≥ 3:1 к `surface` в каждой). От таблицы ТЗ он отличается: критическая `#D13B33`, высокая `#D2601F`, средняя `#B08300`, низкая `#3F85C4`, информация `#6F7C8A` (значения ТЗ не проходили контраст: критическая в тёмной теме 2,3:1, средняя в светлой 2,6:1). Подпись всегда цветом текста; у каждого уровня и решения своя форма значка (`src/ui/icons.tsx`).
- **Контраст** проверяет `src/design/tokens.test.ts`: текст ≥ 4,5:1, граница поля, значки серьёзности и решений ≥ 3:1, в обеих темах. Изменили цвет — запустите `make web-test`.
- **Шрифты** — Onest (интерфейс) и JetBrains Mono (сырое содержимое, идентификаторы, код), лицензия OFL, вариативные woff2 (кириллица и латиница) лежат в `src/assets/fonts/` вместе с текстами лицензий; пакеты npm не подключены. Источник — пакеты `@fontsource-variable/onest` 5.3.1 и `@fontsource-variable/jetbrains-mono` 5.3.0; суммы SHA-256 — в `docs/cert/components.yaml` (тип `font`). Моноширинный шрифт не используется для подписей. Табличные цифры включены на `body` (`font-variant-numeric: tabular-nums`).
- **Компоненты** — `src/ui/`: `Button`, `SeverityBadge`, `DecisionBadge`, `Field`, `Input`, `Select` (родной), `Check`, `Toggle`, `Radios`, `Modal`, `Confirm`, `Hint`, `Panel`, `TabBar`, `Table`, `Banner`, `EmptyState`, `RawText`, `Toaster`. Строятся на примитивах Radix из ADR-0010; новый примитив сначала проверяется макетом и e2e.
- **Страница `/dev/ui-kit`** (`#/dev/ui-kit`, `src/dev/UiKit.tsx`) — токены, типографика и все компоненты, переключатели темы и плотности. Как и `#/dev/radix`, есть только в `npm run dev` и сборке e2e (`vite build --mode e2e` → `dist-e2e/`, `make web-e2e`); в `dist/` и в поставку не попадает. Проверка — `e2e/ui-kit.spec.ts` (обе темы, плотности, шрифты, диалог, отсутствие нарушений CSP).
- **Перед ревью руками:** `npm run dev` → `http://localhost:5173/#/dev/ui-kit`, переключить тему и плотность, пройти Tab по компонентам (фокус виден везде).

## Каркас консоли и вход (задача 2.24, ТЗ 6.3–6.4)
- `src/App.tsx` выбирает экран по `session_state` из `GET /api/v1/me`: нет сессии (401) — вход или, пока в установке нет учётных записей, первичная настройка; `mfa_pending` — код TOTP или код восстановления; `mfa_setup` — подключение второго фактора (QR, затем коды восстановления); `password_change` — смена временного пароля; `active` — каркас.
- Каркас (`src/shell/`): сворачиваемая панель разделов по ТЗ 6.3 (разделы без права скрыты, права проверяет сервер), тема, профиль и выход, выдвижная панель справа (`?panel=…`, прямая ссылка), горячие клавиши `/`, `g e`, `g i`, `?`. Маршруты — хеш (`#/…`), сервер отдаёт только `index.html`. Экраны разделов пока заглушки (2.25–2.27).
- Клиент API (`src/api/client.ts`) работает поверх `schema.d.ts`: `credentials: same-origin`, `X-CSRF-Token` из cookie `__Host-aisec_csrf` в каждом изменяющем запросе, разбор Problem Details, 401 вне входа сбрасывает сессию. Токены и секреты нигде не хранятся, кроме cookie `HttpOnly`; выбор темы живёт только в памяти страницы.
- Ошибки входа и второго фактора одинаковы для любой причины отказа. QR-код TOTP рисуется как SVG из матрицы, которую отдаёт сервер (`src/auth/QrSvg.tsx`).
- e2e (`e2e/console.spec.ts`) идёт против подмены API (`e2e/mock-api.ts`), без сервера; `e2e/watch.ts` валит тест на любое нарушение CSP, ошибку консоли и внешний запрос. Ответы 400/401 API, которые браузер пишет в консоль сам, допускаются.

## Экран «События» (задача 2.26, ТЗ 6.4 п. 4, 6.5, ADR-0015)
- Код — `src/events/`; маршрут `#/events` подгружается отдельным куском (`React.lazy`), раздел виден по `events.read`. Период, фильтр и открытая карточка живут в адресе (`?r=`, `?f=`, `?event=`), поэтому на любое состояние есть прямая ссылка; хранилищ браузера нет.
- Список — `GET /api/v1/events` страницами по 200 по курсору (`useInfiniteQuery`), следующая страница подгружается при прокрутке к концу. Строки виртуализирует TanStack Virtual (в DOM только видимые), TanStack Table 9 отвечает за колонки и их видимость; модель строк таблицы не строится, чтобы не обходить сотни тысяч записей.
- Фильтр — чипы над таблицей (`filter.ts` собирает и разбирает язык ADR-0015: `and`, `=`, `!=`, `in`, `not in`). Условие по тому же полю и знаку добавляется в список значений (`in (…)`). Строку, которую консоль не разобрала, она показывает целиком одним чипом; ошибку проверки возвращает сервер. Сохранённые фильтры — личные, до 50.
- Карточка (`EventCard.tsx`): метаданные, «Почему принято решение» (итоговое действие, правило, режим политики, трассировка), строки матрицы обнаружения, находки, задержки и токены. `details` читается защитно: схема его состав не закрепляет.
- «Показать содержимое»: кнопка только при праве `events.content.read` и `has_content`; причина 3–500 символов вводится в окне и уходит как введена (без правки на клиенте); содержимое выводится `RawText` (текст, без HTML и Markdown, ссылки не кликабельны), держится только в состоянии блока и исчезает при закрытии карточки или кнопке «Скрыть содержимое». Отказы сервера (403, 404, 503 при сбое аудита, 400) показываются отдельными текстами.
- Выгрузка CSV/JSON — `POST /api/v1/events/export` с текущим фильтром и периодом (кнопки только при `events.export`); файл сохраняется как Blob, число строк берётся из `X-Export-Rows`, 422 объясняется.
- Тесты: `filter.test.ts`, `EventCard.test.tsx` (vitest); `e2e/events.spec.ts` против подмены API на 5 000 событий (виртуализация, курсор, чипы, пустой результат, карточка и содержимое с причиной, выгрузка, отсутствие кнопок без прав, строгий CSP).

## Запуск консоли с реальным сервером (стенд для ручной проверки)
`aisec-server` отдаёт собранную консоль на своём порту (`/`), поэтому для проверки нужны PostgreSQL, ключи и TLS-сертификат. Консоль работает только по HTTPS (cookie с префиксом `__Host-`).
1. `make web-deps` и `make web-build` (до сборки сервера: статика встраивается при `go build`). Без сборки консоли сервер пишет предупреждение и работает как чистый API.
2. База: PostgreSQL с пустой базой и ролью-владельцем; `export AISEC_DATABASE_URL='postgres://роль:пароль@127.0.0.1:5432/база?sslmode=disable'`.
3. `go build -o bin/aisec-cli ./cmd/aisec-cli` и `go build -o bin/aisec-server ./cmd/aisec-server`.
4. `bin/aisec-cli migrate`, затем `mkdir -m 0700 keys` и `bin/aisec-cli init -dir keys`. Команда выводит одноразовый токен первичной настройки (24 часа).
5. `go run ./tools/devcerts -out .dev-keys -force` — сертификат TLS для стенда.
6. `bin/aisec-server -listen 127.0.0.1:8444 -tls-cert .dev-keys/server.pem -tls-key .dev-keys/server-key.pem -keys-dir keys -audit-signing-pub keys/audit-signing.pub`.
7. Открыть `https://127.0.0.1:8444/`, принять самоподписанный сертификат. Сначала «Первичная настройка» (токен из шага 4), затем вход; администратору безопасности второй фактор обязателен: отсканировать QR или ввести секрет в приложении-аутентификаторе. Предупреждение о целостности в журнале сервера на стенде ожидаемо (манифеста нет).
